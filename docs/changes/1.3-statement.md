# 1.3 changes: statement draft, EARL and evidence pack

What a user sees from the statement lane of Soundcheck 1.3 (EAA mode): the accessibility statement draft, its `statement:` config block, the EARL export for the W3C WCAG-EM Report Tool, the evidence pack and the WCAG criteria table. The `statement` and `evidence` commands are wired by the CLI lane; their flags and messages are in `1.3-cli.md` and repeated here only where the docs need them in one place.

The criteria tables at the end are generated from `wcag/criteria.yaml` and the vendored axe-core. `TestChangesDocTables` in `wcag/` fails when they drift; `go test ./wcag -run ChangesDocTables -update` rewrites them.

## The statement command

```text
rhythm soundcheck statement [run folder|snapshot] [flags]
      --md                 Markdown (default on a terminal and for .md)
      --html               standalone HTML, printable
      --json               JSON (schema rhythm-soundcheck/statement/v1)
      --earl               EARL JSON-LD for the W3C WCAG-EM Report Tool (.jsonld)
  -o, --output <file>      write to a file (format from the extension); repeatable
      --layout <name>      model (EU 2018/1523 model statement, default) or
                           service (EAA Annex V service information)
      --wcag <version>     2.1 or 2.2; a 2.2 run can be drawn as 2.1, not
                           the other way round
      --config <file>      read statement: (owner, contact, dates) from this file
      --lang <code>        en (only en in 1.3)
      --force              replace a draft file you have edited
Exit codes: 0 written · 2 usage error · 3 no --eaa data, interrupted run, or a file couldn't be read or written
```

- Every `--eaa` run also writes `<run folder>/eaa/statement-draft.md` (layout `model`). It is regenerated on every run, so edits belong in a copy made with `-o`.
- The owner's own text lives in the `statement:` block of `.soundcheck/config.yaml`, not in the draft, so writing the draft again never loses it.
- An unknown layout: `--layout: "<v>" isn't one of model, service (did you mean "service"?)` (exit 2).
- Missing owner, website or email: `statement needs statement.owner, statement.website and statement.contact.email in .soundcheck/config.yaml (rhythm soundcheck init --eaa writes them); a statement without a way to report problems isn't one` (exit 2).
- A run without `--eaa` data: `.soundcheck/runs/<id> has no --eaa results; run rhythm soundcheck snapshot <url> --eaa first` (exit 3).
- An interrupted run: `<run> was interrupted after 17 of 42 pages; a statement from part of the site would leave problems out. Run it again` (exit 3).
- After writing, stderr says how many `[TO DO]` markers are left: `2 [TO DO] markers left`.

## The statement: block

All keys sit under `statement:` in `.soundcheck/config.yaml`. Unknown keys are errors with a did-you-mean, such as `unknown setting "statement.ownr" (did you mean "statement.owner"?)`. Each error names the file and line.

| Key | Required | What it holds | Error text |
|---|---|---|---|
| `owner` | yes | who runs the website | |
| `website` | yes | the public address; the run's own address never appears in the draft | `statement.website: "<v>" isn't the site's address, such as https://shop.example`; `... has a user name or password in it; give the public address`; `... has a query or fragment; give the public address` |
| `contact.email` | yes | where people report problems | `statement.contact.email: "<v>" isn't an email address such as access@shop.example` |
| `contact.phone` | no | phone for feedback | |
| `contact.address` | no | postal address for feedback | |
| `response_days` | no | days to reply, 1 to 365 (0 or absent is unset) | `statement.response_days: must be a number of days between 1 and 365` |
| `country` | no | ISO 3166 alpha-2 code | `statement.country: "<v>" isn't an ISO 3166 country code such as DE, FR or IE`, plus ` (did you mean "DE"?)` for lower case |
| `enforcement` | no | the enforcement authority and how to reach it | |
| `scope` | no | page globs the statement covers | `statement.scope.<i>: "<v>": list page paths that start with /, such as /shop/*` |
| `service` | no | general description of the service (layout `service`) | |
| `known_issues` | no | list of `criterion`, `text`, `until` (optional date) | `statement.known_issues.<i>.criterion: "<v>" isn't a WCAG A or AA success criterion, such as 1.4.3`; `statement.known_issues.<i>.text: says what the problem is`; `statement.known_issues.<i>.until: "<v>" isn't a date as YYYY-MM-DD, such as 2027-03-31` |
| `manual` | no | list of `criterion`, `result`, `by`, `date` (all required) | `statement.manual.<i>.result: "<v>" isn't one of failures found, no failures found, not checked`; `statement.manual.<i>.by: names who checked it`; criterion and date as for known_issues |
| `list_private_paths` | no | `true` lists paths of a logged-in run (default: count only) | |

Limits on every value: `<key>: has a control character (U+001B)`; `<key>: is <n> characters long; keep it under <limit>` (300 for one-line values, 4000 for enforcement, service and known issue text). `scope`, `known_issues` and `manual` take at most 500 entries.

A manual result always wins over the tests for its criterion. The draft records who checked and when. It keeps what the tests found next to it. A manual entry for a criterion the WCAG version lacks is left out with the note `Your manual result for 2.4.11 is left out: WCAG 2.1 has no criterion 2.4.11.`

## What the draft says

Every format starts with the same banner, exactly:

```text
Draft for you to review. Not ready to publish.
Rhythm Soundcheck <version> wrote this on <date> from a check of <n> pages of <statement.website>.
Automated and keyboard tests find some accessibility problems, not all. This is evidence for your own review, not a statement that the site meets WCAG, EN 301 549 or the European Accessibility Act.
Fill in every [TO DO], test the criteria marked "needs a person", then delete this box.
```

Soundcheck never chooses the status. The status section is always a `[TO DO]`:

```text
[TO DO: choose one after your review: "fully compliant", "partially compliant" or "not compliant" with <standard>. Soundcheck does not choose this for you. Its tests found failures of <f> of <total> criteria and could not test <m> of them.]
```

`<standard>` is `WCAG 2.1 level AA / EN 301 549 V3.2.1` or `WCAG 2.2 level AA / EN 301 549 V4.1.1`. In JSON `status` is always `null`.

### Layout model (default)

Follows the EU model accessibility statement (Implementing Decision (EU) 2018/1523), in this order:

1. `# Accessibility statement for <owner>`, `<owner> wants <website> to be usable by as many people as possible.` and the scope: `This statement covers <scope globs>.` or, without `statement.scope`, `This statement covers the <n> pages Soundcheck checked, listed under "Pages checked". [TO DO: set statement.scope to the pages this statement covers, or check that these are all of them.]`
2. `## How accessible this website is`: the status `[TO DO]` above.
3. `## What isn't accessible yet` with:
   - `### Problems found`: one line per criterion with failures, such as `**1.4.3 Contrast (Minimum)** (EN 301 549 9.1.4.3): 1 element on 4 pages: /, /legal/, /shop/ and 1 more page.`, then `[TO DO: for each problem, say in plain words what doesn't work, for whom and what you offer instead.]`. With no failures: `Soundcheck's tests found no failures on <date>. That doesn't mean there are none: <m> criteria need a person.`
   - `### Problems you know about`: from `statement.known_issues`, such as `**1.2.2 Captions (Prerecorded)**: Product videos have no captions yet. Planned to be fixed by 2027-03-31.`
   - `### Accepted or ignored in Soundcheck`: `These problems were found and left out of Soundcheck's results by your ignore rules or accepts. They still count against their criteria above.` Each line names the criteria, the check, up to 3 pages and the reason (or `no reason given`). A change accepted into the snapshot is listed while the run still shows it, with `accepted into the snapshot on <date>; no reason given` (accept takes no reason and the draft doesn't name who accepted it); it still counts as open, as compare counts it.
   - `### Disproportionate burden` and `### Content outside the scope of the law`, each a `[TO DO]`.
4. `## How this statement was prepared`: the date and author as `[TO DO]`, the method (`Rhythm Soundcheck <v> checked <n> pages of <website> on <date> with automated tests (axe-core <axe> with <r> rules plus <c> Soundcheck checks for WCAG <v> A and AA) and a keyboard walkthrough of <p> pages (<w> widgets tested, <f> key flows run).`; the Soundcheck checks are its own reflow and placeholder-label checks, counted apart from axe-core's rules; the advisory overlay check isn't counted), a `[TO DO]` for the owner's manual review, a line on recorded manual results, notes on the run (such as `TLS certificate not verified for this run` after `-k`), `It was last reviewed on [TO DO: date].` and `### What these tests can and can't tell` with the nine fixed limits sentences below.
5. `## Feedback and contact`: `If something on this website doesn't work for you, tell us: email <email>, phone <phone> and post to <address>.` and `We reply within <n> days.` (or a `[TO DO]`).
6. `## Enforcement`: `[TO DO: check this.] If our answer doesn't satisfy you, you can contact: <enforcement>`, or a `[TO DO]` naming the country when `statement.enforcement` is unset.
7. `## Appendix: every WCAG <v> A and AA criterion`: the criteria table (columns Criterion, Level, EN 301 549, How Soundcheck tests it, Result). How Soundcheck tests it leaves out the checks of a module the run didn't turn on (`interact/unlabeled` without interact) and `keyboard/flow` when no key flow ran; a criterion left with none says `not tested: its tests didn't run`.
8. `## Not tested`: pages whose a11y or keyboard audit timed out, failed or was skipped (`<path>: <module> timed out (<reason>); its criteria count as not tested there.`), `Content in frames from <hosts> wasn't tested.`, key flows that didn't run, `<m> criteria need a person: <ids>.`, `Only Chrome was used. The keyboard walk ran at desktop width.`, `No screen reader, voice control or test with disabled users.` and `EN 301 549 clauses 5 (generic requirements, such as closed functionality), 6 (two-way voice communication), 7 (video capabilities), 10 (non-web documents), 11 (software) and 12 (documentation and support services) are outside a website check and weren't tested.`
9. `## Pages checked`: the paths, or for a logged-in run `<n> pages were checked logged in, so their paths aren't listed. Set statement.list_private_paths to true to list them.`

Wording: the EU model's heading for non-compliance is `Problems found`; "content outside the scope of the applicable legislation" is `Content outside the scope of the law`.

### Layout service

EAA Annex V service information (BFSG Anlage 3 in Germany): `# Accessibility information for <owner>`, the same intro, `## About the service` (`statement.service` or `[TO DO: describe the service in general terms, in words people with disabilities can use; or set statement.service.]`), `## How the service meets the accessibility requirements` (status, problems found, known, ignored, disproportionate burden), `## Accessibility features` (`[TO DO: describe how the service works for people with disabilities, such as keyboard use, captions, text alternatives or other ways to reach you.]`), `## How this information was prepared`, then contact, enforcement, appendix, not tested and pages checked as in `model`.

### Results in the criteria table

| Result | When |
|---|---|
| `failures found (<n> elements, <m> pages)` | a test found a failure |
| `no failures found by these tests` | the tests ran and found none (never "passed") |
| `not tested: needs a person` | no test covers the criterion |
| `not tested: its tests didn't run` | the modules that test it didn't run: not in the run, no page's a11y or keyboard audit finished (the keyboard counts when it walked a page) or no page was checked |
| `not tested: W3C now treats it as always met for HTML; the owner decides how to state it` | 4.1.1 Parsing (WCAG 2.1 only) |
| `manual: <result> (<by>, <date>); the tests: <tests' result>` | the owner recorded a manual result |

### Counting

- One problem counts once. A missing label reported by `a11y/label`, `a11y/select-name`, `a11y/placeholder-label`, `interact/unlabeled` or `interact/unnamed-field` on the same element is one finding.
- A finding on 214 pages is 1 element on 214 pages.
- Ignored and accepted findings still count against their criteria: ignoring a problem doesn't fix it.

### Privacy in the draft

- Paths lose their query string and fragment. Tokens after reset, verify, confirm, magic, login and activate are masked, as are secrets.
- The address the run checked (such as a staging host or 127.0.0.1 with its port) and the login user name never appear: the draft uses `statement.website`. This covers the file names and reasons of key flows that didn't run.
- A login name of two characters (such as `bo`) is masked only where it stands alone as a word or path segment: `/users/bo/` is masked, `/books/robot/` stays as it is. A single character is never masked.
- A logged-in run lists no paths unless `list_private_paths: true`.
- Control characters and bidi controls are removed from every format. Markdown special characters in owner text are escaped. The HTML has no scripts, a strict Content Security Policy and prints cleanly in light and dark.

### Fixed limits sentences

The draft, `help eaa` and the README print these word for word:

1. Soundcheck's EAA mode gives you evidence about your site. It is not an audit, not a certification and not legal advice.
2. Many success criteria need a person: meaningful alt text, captions, reading order, plain language. The draft marks them not tested: needs a person, never passed.
3. Only the pages and flows Soundcheck visited, in the states it saw, in Chrome, with the keyboard walk at desktop width. Content in iframes from other sites, PDFs, videos, apps and emails was not tested.
4. The keyboard walkthrough uses Chrome's keyboard events. It is not a screen reader test, not a voice control test and not a test with disabled users.
5. The site decides what Soundcheck sees. A site that serves headless browsers a different page can pass while visitors fail. Overlay widgets don't make a site accessible.
6. EAA mode presses keys on your pages. It holds requests that would change data, blocks downloads and follows no links except skip links. A site that changes data on a GET or on focus can still change. Run it on staging and list your live site under production.
7. Reports contain what your pages showed. Soundcheck masks form values, credentials and tokens it recognises and emails, phone numbers and card numbers in text it writes. Masking is pattern-based: it is pseudonymised, not anonymised. Screenshots are not masked.
8. A signed evidence pack proves who produced it and that it wasn't changed afterwards. It doesn't prove the site was in that state for every visitor.
9. Nothing leaves your machine except requests to your own site and hosts you allow. No telemetry, no hosted service, no AI.

## JSON output

`statement --json` writes schema `rhythm-soundcheck/statement/v1` (`model/schema/statement.v1.json`). Top-level keys: `schema`, `tool`, `version`, `date`, `layout`, `wcag`, `en301549`, `standard`, `status` (always null), `evidence_note`, `todo`, `website`, `owner`, `pages`, `private_pages`, `checked`, `axe`, `axe_rules`, `own_checks`, `totals` (`criteria`, `failed`, `not_tested`), `criteria`, `known_issues`, `ignored`, `not_audited`, `frames`, `keyboard`, `notes`, `limits`. Each criterion has `id`, `title`, `level`, `principle`, `en301549`, `coverage`, `tested_by`, `how_tested`, `result` (`failures_found`, `no_failures_found`, `not_tested` or `manual`), `tests`, `text`, `issues`, `pages`, `paths` and `manual` (or null). Lists are `[]`, never null.

## EARL export

`statement --earl` or `-o <file>.jsonld` writes the JSON-LD evaluation that the W3C WCAG-EM Report Tool 4.1.0 saves and opens, so an evaluator can import it and carry on by hand.

- Scope: website from `statement.website`, title the owner, conformance target AA, the WCAG version.
- Sample: every checked page (none for a logged-in run). Each page's id is `statement.website` plus its path, escaped once: `/%C3%BCber-uns/a%20b/` stays `https://shop.example/%C3%BCber-uns/a%20b/` and `/商品/a b/` becomes `https://shop.example/%E5%95%86%E5%93%81/a%20b/`.
- One assertion per criterion. Outcomes: `earl:failed` (failures found), `earl:cantTell` (no failures found by these tests; Soundcheck never writes `earl:passed`) or `earl:untested`. A manual entry maps the same way: failures found to failed, no failures found to cantTell, not checked to untested.
- Test mode: `earl:semiAuto` when a keyboard check tests the criterion, `earl:automatic` otherwise, `earl:manual` for the owner's manual entries.
- Asserted by `Rhythm Soundcheck <version>`. The summary reads `Soundcheck's tests found failures of <f> of <total> criteria and could not test <m> of them.` followed by the evidence note.

## Evidence pack

Every `--eaa` run and snapshot writes `eaa/evidence.json` (schema `rhythm-soundcheck/evidence/v1`, `model/schema/evidence.v1.json`) in its folder:

```text
.soundcheck/snapshots/eaa-1/            (and .soundcheck/runs/<time>/)
  run.json  pages.jsonl  keyboard/<pageid>.json
  eaa/
    evidence.json                      the pack
    evidence.sig  evidence.pub         after evidence sign
    statement-draft.md                 regenerated on every --eaa run
    written.json                       SHA-256 of drafts written with -o
    focus/<pageid>-<n>.png             element crops
```

- The pack records the tool and axe-core versions (with axe's SHA-256), Chrome, the run options, start and end, `interrupted`, `insecure` (a `-k` run), each page's audit status per module (by path, without its query and with a token in it masked, as the draft masks it: `/reset/•••••/`), the `eaa` summary and the SHA-256 of `run.json`, the pages file, every keyboard trace and every focus crop.
- Each pack names the previous `--eaa` run or snapshot of the same site (the newest one that started before it) and that pack's SHA-256, so the packs form a chain.
- `eaa/` is 0700 and its files 0600. A symlinked `eaa/` is refused: `evidence: eaa is a symbolic link; refusing to write through it`.

### evidence commands

```text
rhythm soundcheck evidence verify [run folder|snapshot]
rhythm soundcheck evidence sign [run folder|snapshot] --key <file>
rhythm soundcheck evidence keygen -o <file>
Exit codes: 0 verified or signed · 1 verification failed (names the file or the gap) · 2 usage · 3 can't read
```

`verify` checks every file of the run and every earlier pack in the chain. Its failures (exit 1):

- `evidence: <file> changed after it was recorded (sha256 differs)`
- `evidence: <file> was deleted after it was recorded`
- `evidence: <file> was added after the pack was recorded`
- `evidence: the run before <id> is missing from the chain`
- `evidence: <prev id>/eaa/evidence.json changed after it was recorded (sha256 differs)`
- `evidence: eaa/evidence.sig doesn't match eaa/evidence.json (signature invalid)`
- `evidence: eaa/evidence.pub is there without eaa/evidence.sig`
- `evidence: <file> isn't a regular file` (a recorded file swapped for a FIFO, device or symbolic link; it is never opened)
- `evidence: the chain loops at <id>`

A pack that can't be read as one reports `evidence: eaa/evidence.json is over 32 MB`, `evidence: eaa/evidence.json has schema "<s>", not rhythm-soundcheck/evidence/v1`, `evidence: eaa/evidence.json lists "<path>", which isn't a file of the run`, `evidence: eaa/evidence.json: "<v>" isn't a SHA-256` or `evidence: eaa/evidence.json: previous run "<id>" isn't a run of the store`.

`<id>` is `runs/<name>` or `snapshots/<name>`.

`keygen` writes an Ed25519 private key (PKCS #8 PEM, 0600) and never replaces an existing file; it prints the public key in base64. `sign` writes `eaa/evidence.sig` (the Ed25519 signature of evidence.json in base64) and `eaa/evidence.pub`. It refuses a `-k` run: `can't sign a run made with -k: TLS wasn't verified`. A file that isn't a key: `<path> isn't a signing key; make one with rhythm soundcheck evidence keygen`, `<path> isn't a signing key (too big)` or `<path> isn't an ed25519 key`.

`verify` checks the signature with the key in `eaa/evidence.pub` as it finds it. Someone who changes a pack and signs it again with their own key still passes, so a reader compares that key with the one the owner published. The key comes from `evidence.SigningKey` (`evidence: eaa/evidence.pub isn't an ed25519 public key` for a bad one); how `verify` prints it is the CLI lane's (`1.3-cli.md`).

Pruning never deletes a run with a pack. A run deleted by hand breaks the chain: `verify` of the run after it reports `the run before <id> is missing from the chain`. A pack written again for an older run chains only to a run that started before it, never to a newer one.

**Kept packs.** Later runs are chained to a snapshot's pack as it was, so a snapshot is never changed under them:

- `accept` into a snapshot with a pack first copies the pack, its signature and every file it lists to `.soundcheck/evidence/<sha256 of evidence.json>/`. Accept rewrites the snapshot's run.json, its pages file and snapshot.json, so it then records the pack again for the accepted state. The new pack has `amends: {sha256, reason: "accept", at}` naming the one it replaces. A signature of the old pack doesn't sign the new one: it is removed (the kept copy has it) and accept says to sign again. Accept prints `note: accept changed run.json, the pages file and snapshot.json of snapshot "<name>", so its evidence pack was recorded again. The pack from before is kept in .soundcheck/evidence/<sha256> with its files: evidence verify of later --eaa runs, which are chained to it, checks that copy and notes it`.
- Taking a snapshot again under the same name, or `snapshots delete`, keeps the old pack the same way: `note: snapshot "<name>" had an evidence pack; it is kept in .soundcheck/evidence/<sha256>, so evidence verify of later --eaa runs still checks their chain`.
- `verify` checks a link whose run no longer matches against the kept copy (files and signature included) and passes with a note on stderr: `note: snapshots/<name> changed by accept after <id> was chained to it; checked the copy kept in evidence/<sha256>` (or `was deleted or taken again`). Verifying the recorded-again pack itself notes `note: snapshots/<name> was recorded again after accept on <date>; the pack it replaced is kept in evidence/<sha256>`. A kept copy that was changed fails: `evidence: evidence/<sha256>/eaa/evidence.json changed after it was kept (sha256 differs)`, or names the kept file that changed.

## The criteria catalogue

`wcag/criteria.yaml` lists every WCAG 2.0, 2.1 and 2.2 A and AA success criterion with its EN 301 549 clause and how Soundcheck tests it. The axe-core rules come from the vendored axe-core 4.14.0 (`wcag/axe_rules.gen.go`, 105 rules, made by `node scripts/gen-axe-rules.mjs`). A rule runs for a version when it has one of that version's tags (2.1: `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`; 2.2 adds `wcag22aa`) and isn't experimental.

Soundcheck's own checks map to these criteria: `keyboard/trap` 2.1.2; `keyboard/not-reachable`, `keyboard/not-operable`, `keyboard/menu` and `keyboard/flow` 2.1.1; `keyboard/focus-lost` and `keyboard/dialog-focus` 2.4.3; `keyboard/no-focus-ring` and `keyboard/focus-invisible` 2.4.7; `keyboard/skip-link-broken` 2.4.1; `keyboard/context-change` 3.2.1; `keyboard/error-not-linked` 3.3.1; `keyboard/focus-obscured` 2.4.11 (2.2 only); `a11y/placeholder-label` 3.3.2; `a11y/reflow` 1.4.10; `interact/unlabeled` 3.3.2 and 4.1.2. `keyboard/skip-link-missing`, `keyboard/escape` and `interact/unnamed-field` map to no criterion. `a11y/placeholder-label` doesn't report checkboxes and radio buttons.

"Partly" means the tests look for some ways the criterion fails. Only a person can say a criterion is met.

An axe rule that can only ask for review never reports a failure, so it doesn't count as a test of its criterion: the rules the vendored axe-core marks `reviewOnFail` (`bypass`, `no-autoplay-audio`, `duplicate-id-aria`, `frame-title-unique` and `aria-braille-equivalent`) and `video-caption` and `audio-caption`, whose check never fails. 2.4.1 keeps `keyboard/skip-link-broken`, which finds a broken skip link but can't show a page has a way past its blocks: with no failure found it reads `not tested: needs a person`, never `no failures found by these tests`.
