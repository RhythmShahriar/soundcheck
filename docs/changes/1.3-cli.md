# 1.3 changes: CLI, config, GitHub Action and README

Everything a user can see that the cli lane added for EAA mode: commands, flags, help topics, messages, exit codes, config, the GitHub Action and the README. Messages go to stderr prefixed `rhythm-soundcheck:` (`rhythm soundcheck:` through the router) unless noted. Exit codes: 0 ok, 1 at or above `--fail-on`, 2 usage, 3 couldn't check, 130 interrupted.

## Flags on snapshot, compare, run, --against and fleet

| Flag | What it does |
|---|---|
| `--eaa` | Accessibility evidence for the European Accessibility Act: modules health, a11y and keyboard, WCAG 2.1 rules and a statement draft in the run folder. `--eaa=false` turns off `eaa: true` from the config file. |
| `--wcag <version>` | a11y rules: 2.0, 2.1 or 2.2. Default `a11y.wcag` in the config file, else 2.1. A compare uses its snapshot's. Recorded in run.json options as `wcag`. |
| `--staging` | This target is a staging site: key flows marked `keyboard: send` may submit on a public address. |

`report` refuses all three: `--eaa doesn't apply to report` (likewise `--wcag` and `--staging`), exit 2.

Modules under `--eaa`:

| You chose | Modules |
|---|---|
| nothing | `health, a11y, keyboard` |
| `--modules x` | x plus a11y and keyboard |
| `--modules +x` | `health, a11y, keyboard` plus x |
| `modules:` in the config | that list plus a11y and keyboard (`--modules +x` adds to it) |
| `--quick` | quick's list plus a11y and keyboard |

Viewports don't change. The settings header starts with `Preset: --eaa: modules health, a11y, keyboard; WCAG 2.1`, or with a chosen list `--eaa: modules visual, a11y, keyboard (--modules kept; a11y and keyboard added); WCAG 2.1` (the kept part names `--modules`, `--quick` or the config file path).

Usage errors (exit 2), checked in this order:

1. `unknown flag --eea (did you mean --eaa?)`
2. `--eaa needs the a11y and keyboard modules; drop --skip keyboard, or leave out --eaa to run without them` (names what was skipped, e.g. `--skip a11y,keyboard`)
3. `--wcag (a11y.wcag): "2" isn't one of 2.0, 2.1, 2.2` (with or without `--eaa`)
4. `--eaa maps to WCAG 2.1 AA (EN 301 549 V3.2.1); use --wcag 2.1 or 2.2, or leave out --eaa to run the 2.0 rules`
5. `--eaa needs Chrome: the keyboard walkthrough and axe use the Chrome DevTools protocol. Drop --browser firefox, or use --modules +a11y without --eaa` (names the engine)
6. `--eaa won't turn off Chrome's sandbox from SOUNDCHECK_NO_SANDBOX alone; add --no-sandbox to the command if you mean it` (also with `--no-sandbox=false`, which asks for the sandbox the variable would still turn off)

Under `--eaa` the `statement:` block of the config is read before the run; a mistake in it is a usage error with the statement package's text.

### compare

- Takes the snapshot's `eaa` and `wcag` unless `--eaa`, `eaa:` or `--wcag` say otherwise. A plain compare of an `--eaa` snapshot is an `--eaa` compare, with every rule above.
- A snapshot that stored no `wcag` compares with the 2.0 rules, except under `--eaa`, which uses 2.1.
- Settings changes listed (and refused with `--strict`, exit 2): `wcag 2.1 -> 2.2 (--wcag)`; `modules health,visual -> health,visual,a11y,keyboard (--eaa)`; for a snapshot taken without it `eaa off -> on (--eaa)`.
- Note before the run (not with `-q`): `note: snapshot "before" was taken without --eaa; keyboard issues will all be new. Take a new snapshot with --eaa`, or `a11y and keyboard issues` when the snapshot didn't run a11y either. Those modules' issues are then compared with none, so each one is NEW or BROKE (any other module that ran only once is still left out). The comparison warning reads `modules differ (snapshot [health visual], now [health visual a11y keyboard]); only modules in both are compared, besides a11y and keyboard, which --eaa added: all their issues are new`.
- Comparison warning (terminal, reports and `warnings` in the JSON), when the a11y module runs: `note: snapshot "before" used the WCAG 2.0 rules; take a new snapshot to add the 2.1 rules` (names 2.2 when that is used now)

### fleet

`fleet <sites.yaml> snapshot|compare --eaa --wcag <version>` passes both to every site after the site's own args. Usage gains `--eaa and --wcag <version> go to every site's command.`

## Settings header and end of run

Header lines (plain view shown; the live view uses the same labels):

- with a11y: `Accessibility: axe-core 4.14.0, WCAG 2.1 A and AA rules, reflow at 320 px`
- with keyboard: `Keyboard: Tab walk on every page (up to 150 stops), menus and dialogs; 1 key flow (keyboard-checkout.yaml) needs --level flows, not run`. Variants: `no key flows`, `1 key flow (x.yaml) runs`, `2 key flows (a.yaml, b.yaml) need --level flows, not run`, `2 key flows (a.yaml, b.yaml) run`.
- under `--eaa`: `Never: submits a form, places an order or types into fields outside key flows` (left out when the interact module runs at `--level submit` or `flows`: it submits forms then, so the promise isn't true)

After every `--eaa` snapshot, run and compare:

- The `eaa` block is in every output format (JSON, Markdown, HTML, JUnit, `-o` files, report.html). `report` of a stored `--eaa` run fills it too.
- `<run folder>/eaa/evidence.json` and `<run folder>/eaa/statement-draft.md` are written (folder 0700, files 0600). Without `statement.owner`, `statement.website` or `statement.contact.email` the draft still gets written with `[TO DO: who runs the website; set statement.owner]`, `[TO DO: the public address of the website; set statement.website]` and `[TO DO: an email address for accessibility feedback; set statement.contact.email]`. When `eaa/` in the run folder is a symbolic link nothing is written through it: `rhythm-soundcheck: <run folder>/eaa is a symbolic link; not writing the EAA files through it` (the run's exit code is unchanged). `statement -o` refuses the same link with the same text before it writes any file (3).
- A file that can't be written: `rhythm-soundcheck: writing <path>: <error>`; the exit code doesn't change.
- After `full report:` and before `next:`:

```text
statement: .soundcheck/snapshots/eaa-1/eaa/statement-draft.md (a draft for you to finish:
           rhythm soundcheck statement -o accessibility-statement.md)
```

- Each ignore rule that matched nothing (not interrupted, not `-q`): `note: ignore rule 2 (a11y/color-contrast on /legal/*) matched nothing; the problem looks fixed: remove it` (`on every page` without pages; a rule without a check shows its title quoted).

Exit code rule under `--eaa`: when a page's a11y or keyboard audit didn't finish (not ok or capped) and the run wasn't interrupted, the exit code is 3 whatever `--fail-on` says, with `rhythm-soundcheck: the accessibility evidence is incomplete: the a11y or keyboard tests didn't finish on 1 page (see "not checked" above), so the statement marks them not tested`. 130 and 2 win over it. An interrupted `--eaa` run writes eaa/evidence.json marked interrupted, eaa/progress.json (`{"pages":42}`, the pages it set out to visit, 0600) for the statement command's `after 17 of 42 pages`, no draft and no `statement:` line. A run made with `-k` records `"insecure": true` in eaa/evidence.json, so `evidence sign` refuses it and `statement` adds the TLS note.

## New commands

### statement

```text
rhythm soundcheck statement [run folder|snapshot] [flags]
      --md                 Markdown (default on a terminal and for .md)
      --html               standalone HTML, printable
      --json               JSON (schema rhythm-soundcheck/statement/v1)
      --earl               EARL JSON-LD for the W3C WCAG-EM Report Tool (.jsonld)
  -o, --output <file>      write to a file (format from the extension); repeatable
      --layout <name>      model (EU 2018/1523 model statement, default) or
                           service (EAA Annex V service information)
      --wcag <version>     2.1 or 2.2; a 2.2 run can be drawn as 2.1, not
                           the other way round
      --config <file>      read statement: (owner, contact, dates) from this file
      --lang <code>        en (only en in 1.3)
      --force              replace a draft file you have edited
Exit codes: 0 written · 2 usage error · 3 no --eaa data, interrupted run, or a file couldn't be read or written
```

- Source: a run folder, a snapshot name or by default the newest `--eaa` run or snapshot. Errors: `no run in <dir>; name a run folder or a snapshot (see rhythm soundcheck snapshots)` (2), `no snapshot named "x"; see rhythm soundcheck snapshots` (2), `no --eaa results in .soundcheck yet; run rhythm soundcheck snapshot <url> --eaa first` (3).
- Formats: `-o` extensions `.md`/`.markdown`, `.html`/`.htm`, `.json`, `.jsonld`; `-o -` is stdout. Errors (2): `pick one format, not --html and --md`; `--md with several -o: each file's format comes from its extension, so leave out --md`; `can't tell the format of s.txt from its extension; use .md, .html, .json or .jsonld`; `-o x.md is given twice`; `--layout: "x" isn't one of model, service`; `--wcag: "2.0" isn't one of 2.1, 2.2`; `the run used the WCAG 2.1 rules; --wcag 2.2 needs a run made with --wcag 2.2`; `--config: <file>: no such file or directory`; `--lang: only en in this version`.
- Refusals: `<run folder> has no --eaa results; run rhythm soundcheck snapshot <url> --eaa first` (3); `<run folder> was interrupted after 17 of 42 pages; a statement from part of the site would leave problems out. Run it again` (3; one page reads `after 1 of 1 page`); `statement needs statement.owner, statement.website and statement.contact.email in .soundcheck/config.yaml (rhythm soundcheck init --eaa writes them); a statement without a way to report problems isn't one` (2).
- `-o` safety: `refusing to write through a symlink: <path>` (3, even with `--force`); a file Soundcheck didn't write, or one edited since: `<path> was edited since Soundcheck wrote it; write to another file with -o, or add --force to replace your edits` (2). Every `-o` is checked before any is written.
- Writes files 0600 and records their SHA-256 in `<run>/eaa/written.json`. stderr: `Statement draft written to <path>`, then `2 [TO DO] markers left` (not with `-q`).

### evidence

```text
rhythm soundcheck evidence verify [run folder|snapshot] [--pub <key>]
rhythm soundcheck evidence sign [run folder|snapshot] --key <file>
rhythm soundcheck evidence keygen -o <file>
Exit codes: 0 verified or signed · 1 verification failed (names the file or the gap) · 2 usage · 3 can't read
```

- verify: `Verified <run>/eaa/evidence.json: every file matches and the chain is whole` (0). Then it prints `signed with key <base64>; check it against the key the owner published`, `signed with key <base64>, the --pub key` or `not signed`. With `--pub <base64>` a pack signed with another key fails with `<run>/eaa/evidence.json was signed with key <base64>, not the --pub key` and an unsigned one with `<run>/eaa/evidence.json isn't signed, so it can't match --pub` (1); a `--pub` that isn't a base64 ed25519 key: `--pub wants the base64 public key evidence keygen printed` (2); with sign or keygen: `--pub goes with evidence verify` (2). Otherwise a failure prints the reason, e.g. `evidence: keyboard/p1.json changed after it was recorded (sha256 differs)` or `evidence: the run before <id> is missing from the chain` (1). A recorded file that can't be read (permissions, a disk error) prints the error and exits 3, not 1.
- sign: `Signed <run>/eaa/evidence.json` (0). Refusals: `evidence sign needs --key <file>; make one with rhythm soundcheck evidence keygen -o <file>` (2); `can't sign a run made with -k: TLS wasn't verified` (2); `--key: <error>` (3).
- keygen: stdout `public key: <key>`, stderr `Private key written to <file>; keep it out of git`. Refusals (2): `evidence keygen needs -o <file> for the private key`; `<file> already exists; keygen never replaces a key, so name a new file`.
- Other errors: `evidence <x>: want verify, sign or keygen`, `--key goes with evidence sign`, `-o goes with evidence keygen` (2); `<run folder> has no evidence pack (eaa/evidence.json); only --eaa runs write one` (3).

## init, flows init, accept and history

- `init --eaa` writes the config with `eaa: true`, the `modules:` line commented out and commented `a11y:`, `keyboard:` and `statement:` blocks (placeholders `"[your organization]"`, `"https://[your public address]"`, `"accessibility@[your domain]"`, under `Everything here is published in the statement: give a role address such as accessibility@ rather than a person's own email or phone.`), plus `.soundcheck/flows/keyboard-checkout.yaml`. stdout: `Wrote .soundcheck/config.yaml. Every setting is optional; edit what you need.`, `Wrote .soundcheck/flows/keyboard-checkout.yaml, a key flow to edit; it runs with --level flows.` (or `Kept <path>, which is already there.`), `Fill in statement: before you run rhythm soundcheck statement.`
- `flows init --keyboard` writes keyboard-checkout.yaml, keyboard-contact.yaml, keyboard-dialog.yaml and keyboard-menu.yaml, then `Edit them, then run them with --level flows: they press keys only; keyboard: true holds every request that would send data.` A file that exists is kept and named (`Kept <path>: it's already there`) and the others are written (0), so it works after `init --eaa`, which writes keyboard-checkout.yaml. With all four there: `the four key flows are already in <dir>; nothing was written` (2).
- `accept` takes BROKE and NEW ids like CHANGED ones. The `--page`/`--check` form prints `Accepted <n> changes` once.
- `accept <id>... --ignore --reason <text> [--until YYYY-MM-DD]` writes an ignore rule per id into .soundcheck/config.yaml (`check`, `pages`, `source` or `title`, `until`, `reason`): `Ignored <id> <check> (<pages>): rule added to .soundcheck/config.yaml`, then `Commit .soundcheck/config.yaml to share the rules; the snapshot is unchanged.` Errors (2): `--ignore needs --reason: say why this is known`; `--reason and --until go with --ignore`; `--ignore takes change ids, not --page and --check`; `--until: "soon" isn't a date like 2026-12-31`; `no change "zz" in this comparison`. A change on a page whose path has a `*` (which a page glob reads as any text) is refused before anything is written, exit 3: `can't ignore <id>: page "/a*b/" has a *, which an ignore rule reads as any text; add the rule to config.yaml by hand`. Other page characters, `[` and `?` included, are literal in a page glob and are copied as they are. The change's source is written as it is (`source: input[name="email"]`), so the rule matches it in the next comparison; a `*` in a selector matches itself.
- `history --metric a11y` and `--metric keyboard`; a wrong name: `--metric: "a11" isn't one of lcp, tbt, ttfb, a11y, keyboard (did you mean "a11y"?)` (2).

## Config

- New keys `eaa`, `a11y`, `keyboard`, `statement` and `ignore[].source` (decoded by their modules).
- The config file is read up to 1 MB: `<path> is larger than 1 MB` (2). More than 100 YAML aliases, or aliases that add more than 10,000 values once expanded: `<path> line <n>: config.yaml uses too many YAML aliases`; deeper than 20 levels: `<path> line <n>: config.yaml nests settings more than 20 levels deep` (2).
- `ignore[].source` is a glob like the other fields, where only `*` is special: any text is valid and a selector's brackets match themselves. An empty rule: `rule 1 has nothing to match: give it a check, a title, pages or a source`.

## GitHub Action

New inputs:

| Input | Default | Meaning |
|---|---|---|
| `eaa` | `"false"` | `"true"` adds `--eaa` |
| `statement` | `"false"` | `"true"` writes `accessibility-statement-draft.md` in `working-directory` after the run and adds it to the artifact; replaces a file of that name in the workspace |
| `wcag` | `""` | passed as `--wcag` |

New outputs: `statement` (the draft's absolute path, empty without `statement: true` or when it couldn't be written), `a11y-open` (open accessibility and keyboard problems; empty for a run without `--eaa`), `criteria-failed` (WCAG criteria with failures; empty without `--eaa`). They are read from the `eaa` block of the JSON report, which isn't uploaded. `incomplete` is `true` when an `--eaa` run exited 3 because the a11y or keyboard tests didn't finish on some pages (empty otherwise): the job summary, JUnit, HTML report, statement draft, the other outputs and (mode snapshot) the baseline cache are still written, the summary and the PR comment end with `**The accessibility evidence is incomplete:** the a11y or keyboard tests didn't finish on some pages (see "not checked" in the report), so the statement marks them not tested and the job fails.`, the log gets `::error::` with Soundcheck's line and the step then fails. Any other exit 3 is still `Soundcheck could not check:`.

- `eaa` or `statement` other than true or false: `the eaa input is "yes": use true or false` in the job summary (exit 2).
- A draft that can't be written (no `statement:` block, no `--eaa` results) warns `::warning::Soundcheck couldn't write the statement draft: <last line>` and the job goes on. No draft is attempted when Soundcheck couldn't check (exit 2 or 3).
- The report artifact is kept for 14 days (`retention-days: 14`); the `upload` input says reports can show logged-in pages.
- The job summary and the comment are the Markdown report as before: counts and rule ids, no issue details.
- `fail-on` keeps its default (broke when comparing, error otherwise): with `eaa: true` that fails on a new keyboard trap only; `fail-on: new` fails on any new accessibility problem.
