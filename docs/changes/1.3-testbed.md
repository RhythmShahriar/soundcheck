# 1.3: testbed and benchmark

Lane testbed. Everything here is under `testbed/`; `docs/benchmark.md` gains the EAA section when the release run regenerates it (`make -C testbed bench`). Nothing changes the `rhythm-soundcheck` binary, its flags or its output. The notes are for the `Soundcheck-Benchmark` wiki page, the testbed README and the release notes.

## New scenarios: s49 to s91

`testbed/scenarios.yaml` now has 91 scenarios. The 43 new ones are EAA mode's (PRD 16.1). Each runs with `--eaa` and names the module that should catch it: `a11y` or `keyboard` (`health` for s86).

- **Broken, must be caught** (s49 to s76): keyboard traps (s49 coupon field, s75 a dialog without Escape, s76 a reload trap), lost and missing focus (s51, s53), dialogs without containment (s52), focus styles removed (s54), a skip link to a missing `#main` (s55), a div for a menu toggle (s56), unreachable wishlist and Place order buttons (s57, s70), hover-only submenus (s58), invalid or missing autocomplete, labels and placeholders (s59, s60, s68), low contrast (s61), no `lang` (s62), images without `alt` (s63), errors by colour only (s64), consent banners and zoom locks (s65, s66), a custom element without a label (s67), a promo bar that won't reflow (s69), a select that navigates on focus (s71), a closed off-canvas menu that stays tabbable (s72), an overlay script (s73) and a page too big to audit in time (s74, which must give exit 3 and `not checked`, never FIXED).
- **Good and hard good, must stay quiet** (s77 to s89): correct dialogs, modals and focus rings, a live region, an old backlog of 300 contrast problems with one of the first 20 fixed (s83 expects FIXED, never NEW), frames from the same and another origin (s84), a checkout on a busy machine (s85), a checkout that answers 500 (s86: BROKE health; the statement lists it as not audited), a snapshot taken by Soundcheck 1.2 (s87), a page with side effects on GET and on focus (s88) and a small site with no known accessibility problems (s89, also checked in every control round).
- **Broken, added after the release review** (s90, s91): a page that never loads under `--eaa` (s90, which must give exit 3 and `not checked` for a11y and keyboard, never FIXED; the statement lists the page as not tested) and controls whose id, name and class hold a token, a JWT and email addresses (s91, under the canary sweep).
- Each waits for the 1.3 lane that ships its detector (`pending: axe`, `keyboard`, `flows`, `statement`, `cli`); the benchmark lists those apart and doesn't count them until the mark is dropped.
- New pages: `testbed/php/a11y/*.php` on the plain-PHP site (also under `php -S`) and on WordPress `/my-account/`, `/s51-newsletter/`, `/s52-modal/`, `/s54-focus/`, `/s55-skip/`, `/s56-toggle/`, `/s58-submenu/`, `/s62-lang/`, `/s63-gallery/`, `/s73-overlay/`, `/s80-skip/`. An existing testbed needs `make -C testbed reset`.
- Testbed pages never reach an outside host, logged in or not: the new mu-plugin `wp/mu-plugins/testbed-local.php` turns off avatars and the front-end admin bar, which made a logged-in page load Gravatar images from `secure.gravatar.com`. The accessibility preflight (`TestPreflight`) fails every request to a host outside the testbed and lists it as an error.
- New port: the plain-PHP site is published a third time on `127.0.0.1:18812` (`TESTBED_PHP_FRAME_PORT`), the other origin of s84's payment frame.
- Step zero: both good states were cleaned until the testbed's own audit (axe-core with the WCAG 2.1 A and AA tags, placeholder labels, reflow, a Tab walk) finds nothing: a skip link to `#main`, landmarks, a visible focus ring, contrast. `testbed/README.md` has the before and after counts. `TestGoodStateIsClean` asks the same of an `--eaa` run once the lanes are merged.

## New manifest fields

`all`, `same`, `backlog`, `fixture`, `flows`, `says`, `within`, `control`, `compare_args` (flags for compare only: s49's `--fail-on broke`, which snapshot refuses); `harness` takes one value or a list; `pending` takes `true` or a lane's name; change matchers gain `source` and `count`. The header of `scenarios.yaml` documents each.

Key flows copied into the runs: `testbed/flows/keyboard-contact.yaml` (s64), `keyboard-checkout.yaml` (s70) and `keyboard-account.yaml` (s68, `login: true`). Soundcheck visits pages anonymously and logs in only for the leak test and flows, so s68's account page reaches the keyboard walk's trace through its key flow; its missing label waits for `--eaa` to audit logged-in pages (see the scenario's note).

## Harnesses

After each compare the benchmark runs the scenario's harnesses. Any problem makes the scenario **missed**, even when its expected change was reported. The scoreboard says why, for example `the expectation held (NEW a11y/label …) but harness: orders: state/orders.txt went from 0 to 1 during the scenario`.

| Harness | Scenarios | Fails when |
|---|---|---|
| `statement` | s50, s84, s86, s89, s90 | `rhythm-soundcheck statement -o statement.md` fails, or the draft lacks the evidence note, `not tested: needs a person` or the scenario's `says`, or uses `complian`, `conform`, `certif`, `passes WCAG`, `fully accessible` or `guarantee` outside the fixed disclaimer and the owner's status choice in a `[TO DO]`, or holds a canary |
| `requests` | s68, s73, s84, s88, s89, s91 | a page, redirect, resource or failed request in any stored run went to a host other than `localhost`, `127.0.0.1`, `::1` or a compose service (`db`, `wp`, `cli`, `php`) |
| `orders` | s49, s70, s85, s88 | `state/orders.txt` (the shop's orders) or `state/sidefx.txt` (s88's GET and focus side effects) changed during the scenario |
| `canaries` | s68, s84, s91 | a canary shows up in any file under the run's `.soundcheck/` or in `good.json`, `compare.json` or `statement.md`. The canaries (`email`, `phone`, `token`, `data`, `field`, `aria`, `query`, `text` and s91's `idtoken`, `namejwt`, `idemail`, `classtoken`, `trapemail`) are made at run time, written to `state/canaries` for the pages and removed afterwards; the message names the canary and the file, never its value |

The statement harness writes a `statement:` block into the run's config: owner `Testbed Coffee Roasters`, website the site's address, contact `access@example.test`.

## The EAA mode section of docs/benchmark.md

The benchmark writes a new `## EAA mode` section, between `<!-- eaa:begin -->` and `<!-- eaa:end -->`:

- the evidence note and the framing of PRD 15 item 10 ("The testbed is written by the same people as the tool. …")
- a headline: `**Caught N of M broken scenarios.** P more wait for a detector that isn't merged yet (…). **False alarms: A of G good scenarios, F** in C `--eaa` compares of unchanged sites.` with the target of PRD 16.3 beside it
- the scenarios table: expected result, harnesses, Soundcheck's result, the detector (merged, or pending with its lane) and the other tools
- false alarms in the `--eaa` control pass (10 rounds on both sites and on s89's page, two compares each)
- determinism: issue keys that differ between the snapshots of the unchanged sites (target 0)
- cost, median and p95 seconds per page: a default run, an `--eaa` run, the a11y audit (`--modules health,a11y` minus `--modules health`), the keyboard walk, one key flow (s70's on the checkout) and the whole `--eaa` run against a default one, with core count, OS, Chrome, axe-core with its tags and the date; the targets beside them (a11y at most 2 s median, walk at most 3 s median, a key flow at most 15 s, the whole run at most 3 times a default one) and `**over**` on a measurement above its target
- coverage from the WCAG catalog for 2.1 and 2.2: criteria with automated tests, keyboard tests and none (`needs a person`), with a collapsible list of every criterion
- other tools when installed: the axe-core CLI (`@axe-core/cli@4.14.0`, WCAG 2.1 A and AA tags), pa11y (`pa11y@10.0.0`, WCAG2AA) and Unlighthouse: what each caught (a violation in broken that good lacks), its false alarms on good scenarios and its violations in good states

The classic scoreboard and its control pass no longer count the EAA scenarios or the `--eaa` rounds.

## Running it

```sh
make build
make -C testbed up
make -C testbed bench-eaa                      # go run -tags testbed ./testbed/bench -only eaa
make -C testbed bench-eaa ARGS="-tools axe,pa11y"
make bench                                     # everything, the EAA section included
```

- `-only eaa` keeps the control pass (10 rounds) unless `-control` is given; other `-only` lists still skip it.
- `-only eaa` rewrites only the EAA section of `docs/benchmark.md`; a full run rewrites the whole file.
- `-tools` knows `axe` and `pa11y` besides `backstop`, `lychee` and `unlighthouse`. The axe-core CLI needs a ChromeDriver that matches Chrome.
- Work folders: `testbed/bench/work/<id>/` (with `statement.md`), `work/control/eaa-<site>/` and `work/control/s89/`, `work/cost/`. `work/results.json` gains `cost` and, per control round, `eaa` and `issue_keys`.
